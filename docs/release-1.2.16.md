# VLESS Card 1.2.16 — море и проверка накопленных функций

- **Анимированные волны на фоне интерфейса.** Четыре спокойных слоя, без видеофайла, загрузки из сети или дополнительных библиотек. До 20 перерисовок/с, состояние движения читается только при отрисовке фона, а не обновляет всю страницу. Настройки → Оформление: «Море на фоне», «Анимация волн».
- **Автоматический статичный режим:** уход приложения в фон, системная экономия, батарея ≤20% без зарядки, нагрев батареи 41°C/39°C на зарядке или Android moderate+, системная шкала анимации 0. Переключение теплового статуса отслеживается на Android10+. Неподвижный фон остаётся видимым; AMOLED не переопределяется морем.
- **Читаемость всех основных экранов:** тёмное море, непрозрачные карточки, подписи onSurfaceVariant вместо низкоконтрастного серого.
- **Нативное ядро только по необходимости.** Убрана eager-загрузка Xray при запуске Application (включая редкую телефонную диагностику). Действия, которым нужно ядро, и VPN инициализируют его сами; ошибки init входят в обработку ошибки соединения. Geo assets записываются AtomicFile, пустой ресурс не считается готовым.
- **Отмена проверок действительно закрывает дочерние задачи.** Пул дополнительных тестов ограничен 12 работниками. Все дополнительные результаты одной пробы имеют общий 40-секундный бюджет вместо последовательных ожиданий по 40 секунд каждый. Таймаут отменяет future, interruption родителя не проглатывается, finally отменяет HTTP и освобождает свой connection pool. Dispatcher каждой пробы отдельный, поэтому отмена не отменяет запросы другой пробы.
- **Проверка наличия обновления не ждёт как загрузка APK:** metadata HTTP timeout 12 секунд, read 8 секунд; downloading APK сохраняет длинный таймаут и все SHA-256/package/version/certificate проверки. Флаг проверки сбрасывается finally.
- **Проверена опубликованная история.** 145 публичных записей к завершению обзора (144 при первом сборе плюс опубликованный во время работы 1.2.15), все доступные описания извлечены: 107 с текстом, 38 без. Сверены ключевые темы с текущим кодом; не заявляется полный аудит diff каждого исторического APK. README теперь описывает реальную Xray/hev архитектуру вместо старых sing-box/Room/экспериментальной LLM.

## Проверки и ограничения
Новые JVM-регрессии проверяют условия остановки волн, геометрию/плавность/повтор периода, сохранение настроек, таймаут и отмену futures. Отдельно проверен HTML-макет палитры и ключевых кадров; это не скриншот Android-приложения. Полный native build/подпись/Android11+14 install/Keystore gates выполняет CI. На реальном телефоне батарея, плавность и все вкладки пока не измерены; море можно полностью выключить.

Отправка телефонных отчётов всё ещё отключена, общий ключ в APK не возвращается. Backup не становится зашифрованным из-за шифрования локального state. Фон не управляет чужими приложениями и не охлаждает физически устройство.

Полный индекс просмотренной публичной истории и конкретные границы проверки: `docs/release-history-audit-1.2.16.md`.

## Дополнение перед выпуском: быстрый подбор
- После первого успешного HTTPS-маршрута отменяются уже запущенные соседние пробы: закрывается активный HTTP Call, освобождаются временное ядро и слоты. Отменённые пробы не записываются как нерабочие и не обучают модель на ложной ошибке. Полная проверка без stopAfter по-прежнему собирает все результаты.
- Один автопоиск не проверяет повторно те же маршруты в последующих быстрых волнах и после обновления подписок. Новые маршруты продолжают проверяться; поиск маскировок остаётся отдельным этапом.
- Недавняя неудача мягко сдвигает маршрут в конец очереди на 60 секунд, только в той же сети и с той же маской. Это память процесса на максимум 512 записей, не постоянный запрет; если других кандидатов нет, такой маршрут всё равно проверяется.
- Облачный кеш применяется до снимка состояния; используются подсказки точной сети с резервом семейства сети. Лёгкая проверка не стирает известные результаты YouTube/Telegram и успешной большой загрузки; новый успех снимает старый отрицательный bigOk до подробной перепроверки.
- Перепроверка старого набора ограничена 3,5-секундным HTTP-бюджетом на пробу вместо старых 9 секунд. Это не обещание всего подключения за 3,5 секунды: инициализация ядра, DNS и ограничения сети могут добавить время.
- Добавлены тесты отмены, ограничения параллелизма, мягкого cooldown, сетевой/масочной изоляции и сохранения обычного полного режима. Ускорение на реальном телефоне пока не измерено.
