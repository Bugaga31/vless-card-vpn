# Следующая итерация: защита конфигураций и исправление транспорта

Статус: исходники и тесты, не опубликованный подписанный APK. Изменения включают исправление поиска «Авто» из предыдущего коммита.

## Защита хранения

Параметры каждого узла сохраняются одним authenticated payload: AES-256-GCM, случайный 96-битный nonce и 128-битный authentication tag. Идентификатор записи привязан через AAD; перенос ciphertext в другую запись не проходит проверку.

Ключ создаётся в Android Keystore и не экспортируется. Используется стандартный JCA/Android provider, без самодельного криптографического алгоритма. Аппаратная защита зависит от устройства и не заявляется без проверки. При расшифровании отсутствующий ключ не создаётся заново.

В payload входят имя, адрес, порт, UUID/пароль, протокол, flow/security, SNI, fingerprint, ключ REALITY, shortId, remark, country/source, transport, wsHost, wsPath и serviceName. Прежние открытые столбцы заменяются нейтральными значениями. Избранное, активный ID, время и статистика остаются незашифрованными метаданными.

Room schema 1 → 2 мигрирует существующие записи в транзакции, сохраняя ID, избранное, активное состояние и статистику. `fallbackToDestructiveMigration` удалён. Сбой миграции должен откатывать транзакцию, а не удалять серверы. При недоступном ключе или повреждении записи интерфейс показывает предупреждение и блокирует запуск «Авто»; данные не стираются. Чтение/расшифрование списка перенесено на IO.

SQLite использует TRUNCATE journal; миграция включает secure_delete. Это **не гарантия форензического удаления** прежних страниц, OS snapshots или старых резервных копий. Это также не SQLCipher: весь файл базы и метаданные не шифруются.

Границы: эта правка защищает payload узлов в Room. URL подписок защищаются существующим отдельным SubscriptionStore. Прочие SharedPreferences, включая старые rescue-закладки с адресами и необязательный GitHub API token, этой миграцией полностью не защищены. Приложение отключает обычный backup, но это не утверждение об отсутствии всех копий на устройствах разных производителей.

Шифрование хранения не меняет внешний вид сетевого трафика и не обеспечивает обход блокировок. Установленные ранее VPN/ByeDPI/TLS-профили сохранены; новый сетевой шифр, Tor/Orbot и zapret не добавлены.

## Критическое исправление сохранения транспорта

Старая Room entity не сохраняла transport/wsHost/wsPath/serviceName. После чтения WS/gRPC-узел получал TCP-параметры по умолчанию, даже если URI был правильно разобран. Теперь параметры сохраняются внутри encrypted payload и возвращаются без изменения.

**Уже потерянные в schema 1 пути и параметры восстановить невозможно.** Для старых WS/gRPC-узлов нужно заново импортировать исходную конфигурацию или обновить подписку. Миграция не придумывает отсутствующий Host/path и не подменяет SNI. Избранное нового повторно импортированного узла стоит проверить, особенно при поиске только по избранному.

## Дизайн

- Частично рабочий маршрут отображается как «Частичный доступ», с отдельными результатами сайтов, а не зелёным обещанием полной доступности.
- В настройках появилась спокойная карточка с объяснением границ защиты конфигураций.
- Ошибка хранилища отображается отдельным предупреждением: без автоматического удаления, фиктивного подключения и приглашения использовать недоступные данные.
- Проверяются светлая/тёмная темы, крупный шрифт 150% и существующий 320 dp layout.

## Перед выпуском APK

Android Keystore и миграцию нужно запустить на реальном Android 13 или эмуляторе. Скомпилированные instrumentation-тесты проверяют миграцию, откат при ошибке и неэкспортируемый Android key — их наличие не означает, что они были выполнены.

Для обновления существующей Auto-установки требуется прежний signing keystore (сертификат SHA-256 `a90f21276a337bb1cbec545d23fce00e173b46cec83f5af015076e53d5488d54`). В текущей среде этот приватный ключ отсутствует. Новым сертификатом нельзя молча подписать совместимое обновление. Нельзя исправлять это удалением приложения: это уничтожит его данные и ключи Android Keystore.

Нужен прежний signing keystore или согласованная отдельная тестовая установка с переносом подписок. Секретный keystore/пароль нельзя коммитить в GitHub. Существующий legacy main-workflow всё ещё требует отдельного обновления под NDK и стабильную подпись; он не является проверенным способом выпуска этой ветки.

Новые изменения не входят в ранее выданный APK 1.0.46. Доступность YouTube/Telegram и маршрут приложений через TUN на realme пока не доказаны.

## Сетевое разбиение: не путать с защитой базы

ByeDPI теперь имеет три настоящих набора параметров нативного движка:

| Вариант | Аргументы | Назначение |
| --- | --- | --- |
| TCP | `--split 1+s` | Изменяет разбиение передачи внешнего TCP-потока |
| TLS-записи | `--tlsrec 1+s` | Делит ClientHello между TLS-записями |
| Сочетание | `--split 1+s --tlsrec 1+s` | Использует оба механизма |

Это не разделение содержимого HTTPS-запроса на независимые запросы и не новый криптографический алгоритм. Параметры применяются к внешнему соединению VPN, а не к прямому незашифрованному выходу приложений.

«Авто» распределяет первые варианты по разным узлам, учитывает историю неудач и сначала пробует ранее подтверждённый вариант. Для одного узла доступны все три варианта, совместимый профиль и фрагментация ядра. Общий бюджет остаётся 36 попыток; он не гарантирует, что будут проверены все варианты всех импортированных узлов. Память сохраняет конкретный вариант ByeDPI только после успешной проверки всех требуемых веб-ответов. При возврате частичного маршрута восстанавливается тот же вариант.

Локальный Linux smoke-test собирает pinned native source и проверяет все три режима на TLS-сервере с проверкой сертификата и ожидаемым HTTPS 204. Он также читает заголовок ClientHello до TLS handshake и проверяет фактическое изменение границы TLS-записи для режимов с `tlsrec`. Это не packet-capture доказательство конкретного количества TCP-пакетов и не тест DPI провайдера. Совместимость REALITY/Android child-process и результат в сети пользователя ещё требуют проверки на устройстве.


## Результаты проверки исходников

- 199 JVM-тестов: 0 failures, 0 errors. Android Lint: 0 errors, 41 warning.
- Debug и Release Kotlin скомпилированы; instrumentation APK собран, но не запускался на устройстве.
- 30 кадров Compose отрендерены. 19 ранее визуально проверенных кадров побайтно совпадают; 11 актуальных кадров проверены отдельно, включая новые состояния, темы и крупный шрифт. 18 пар обычного текста соответствуют WCAG AA.
- Три нативных режима ByeDPI прошли локальную проверку TLS/HTTPS и формы TLS-записей на Linux. Android-native binary не пересобирался в этой проверке и работа в сети пользователя не проверялась.
- `qa/build-compatible-auto-release.sh` проверен синтаксически и действительно отклоняет текущий новый debug-сертификат до сборки/публикации APK. Для полного прогона нужен исходный signing keystore и NDK 27.2.12479018.

Команда проверки: `GITHUB_RUN_NUMBER=48 ./gradlew -PautoPreview=true :app:recordPaparazziDebug :app:compileReleaseKotlin :app:assembleDebugAndroidTest :app:lintRelease -x :app:buildByeDpi` (Java 17, Android SDK 34).

Команда нативного теста: `python3 native/host-smoke-test.py`.
