# VLESS Card 1.2.73 · Experimental — Auto Recovery

## Исправления по четырём симптомам
- **Смена сети / не подключается.** quickRecheck после полного сброса результатов теперь явно проверяет HTTPS + Telegram MTProto. Раньше youtube=false неявно отключало и Telegram, хотя последующий отбор требовал его подтверждения. Валидация получает до 8,5 с, отдельная проба до 6,5 с; первый подтверждённый маршрут выбирается без предварительного сравнения загрузок. Это лимиты, а не обещанное время подключения.
- **Долго ищет.** Облачный blocked больше не удаляет конфигурации из каталога для локальных проб. Он остаётся мягкой подсказкой порядка; облако не выдаёт локальный PASS. Если все оставшиеся маршруты на cooldown, пользовательский поиск может проверить до трёх разных хостов вместо одного; фон по умолчанию по-прежнему один. Реальные ограничения параллельности телефона сохраняются.
- **Повторяет одну волну.** В foreground-поиске курсор продвигается при постановке небольшой волны, а не только после её завершения: внешний таймаут больше не возвращает поиск постоянно к тем же восьми ссылкам. Scheduled не означает проверено или отказ. Повторный обход каталога после исчерпания/60 с и сброс при смене сети сохранены.
- **Маскировки не доходят до проверки.** В continuous-поиске лёгкий Hello-rescue вынесен из общего 10-секундного бюджета в собственный ограниченный этап до 3,8 с раз в три волны, начиная с первой. До двух серверов / четырёх вариантов, обязательны HTTPS и MTProto. Старый TCP-positive больше не условие допуска к этому этапу. Дополнительный бюджет может увеличить длительность неуспешной волны; это устранение starvation, не гарантированное ускорение.
- **Подключён, но Telegram не отвечает.** MTProto использует отдельный ограниченный пул из восьми рабочих потоков и собирается до ожидания загрузок; media-проверки не могут занять все его рабочие потоки. Бюджет пересчитывается при старте задачи. Это не проверяет аккаунт, все DC, медиа и звонки.
- **Стартовая проверка.** Обычный Auto проверяет HTTPS, Telegram и SOCKS-UDP DNS, не ожидая загрузку YouTube. Для YouTube через DPI отдельная медиа-проверка остаётся. YouTube без пробы показывается неизвестным, а не успешным.
- **Обрывы / восстановление.** Два подтверждённых HTTPS-сбоя обычного Auto запускают поиск независимо проверенного резерва с сохранением TUN, вместо первого же hard-restart того же сервера. Для DNS/TUN-сбоев перезапуск остаётся. Паузы между неуспешными волнами восстановления теперь 3–15 с вместо 5–60 с; это может увеличить расход трафика/батареи во время сбоя. Ограничения звонков и сна сохраняются.
- **Поиск резерва.** Общий attempted-курсор сохраняется между попытками на одной физической сети. Сначала до четырёх известных резервов с новой HTTPS+MTProto-пробой; затем следующая ограниченная host-волна, а не повторная тяжёлая эволюция масок/CDN-sweep перед каждым поиском. Источники обновляются параллельно с ограниченным бюджетом. Старый works без новой сервисной валидации не выбирается.
- **Гонки и отмена.** Восстановление проверяет core, SOCKS, ключ и handle физической сети перед reconnect, в том числе под lock; CancellationException не проглатывается. Лёгкая смена маски не перезаписывает более свежий checkedAt той же маски.
- **Неподтверждённый Telegram / DNS.** Watchdog перепроверяет такие состояния через короткий интервал, а не здоровый интервал ожидания. Неизвестный MTProto не становится ложным отрицательным обучающим примером.

## Что не обещаем
Не измерены ускорение на телефоне владельца, устойчивость на российских операторах или превосходство над конкурентами. SOCKS+UDP DNS не независимая проверка полного Android app→TUN-пути. Изменения не чинят выключенный чужой сервер и не добавляют серверную поддержку WebRTC/QUIC-мимикрии. TLS-верификация не ослаблялась; прямого интернет-fallback нет. Невидимость DPI не заявляется.

## Основания и исследования
Прочитаны статья The Bell, первичный auditor-faq 2017 года и описание AIVPN. Выводы и ограничения — в research-auto-r184.md. Код AIVPN не импортировался, его runtime/безопасность не проверялись.
