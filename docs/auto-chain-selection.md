# Экспериментальный подбор цепочек Auto — не включён в приложение

База: v1.2.54, `7d83d3e8b58a9673154c16c4a3fb9a2d200715dd`.
Работа отделена от нейромодели: текстовая модель не выставляет PASS и не управляет VPN.

## Что реализовано

`AutoChainSelection` — изолированный механизм выбора с интерфейсом адаптера:

- До 8 уникальных цепочек из первых 32 предложений; без перебора полного каталога.
- Один монотонный бюджет 15 секунд, до 3 секунд на запуск/измерение одного варианта.
- Холодный Tor не запускается заново для каждой попытки: сначала отдельный прогрев,
  затем допуск реально готового Tor. Определять готовность только TCP-портом нельзя.
- Tor требует явного согласия пользователя; UDP через Tor не допускается.
- Несовместимые и не реализованные адаптером схемы исключаются до запуска.
- Проверяется доказательство передачи тела, а не ping/TCP-connect. Минимум 16 KiB,
  максимум 4 MiB в одном образце; адаптер обязан проверить ожидаемое HTTPS-тело.
- Старый образец, другой network generation, другая маска/мост/стратегия/цепочка не
  могут подтвердить новый вариант. Адаптер должен менять generation при смене
  Tor circuit/NEWNYM, а не только сети телефона.
- Telegram/YouTube PASS имеют приоритет перед data-only UNKNOWN независимо от скорости.
  Явный FAIL исключает вариант. Если подтверждения нет, выбирается максимум один
  честный fallback при финализации, а не сразу после первого HTTPS-успеха.
- Профили выбора: скорость загрузки, минимальная задержка, компромисс скорости/задержки.
  Это лучший **из измеренных** вариантов, не обещание глобально самого быстрого сервера.
- Измерения загрузки последовательны: параллельные загрузки сами искажают результат.
- Отмена распространяется наружу; результат не применяется к Store/VPN. Смена сети
  отбрасывает все результаты. При ошибке cleanup следующий адаптер не запускается.
- ID — SHA-256 идентификаторов конфигурации без пользовательского payload/credentials.

Интерфейс кооперативный. `open` обязан очистить частично созданные ресурсы при ошибке
или отмене; `close` должен быть ограниченным и неблокирующим. Coroutine timeout не
может принудительно остановить произвольный зависший native вызов. Жёсткую остановку
процессов обязан реализовать реальный runtime-адаптер.

## Порядок цепочки

Названия перечисляют фактические сетевые хопы **от устройства к интернету**:

| Схема | Генератор изолированного Xray-конфига | Пояснение |
| --- | --- | --- |
| SERVER | Есть | Через выбранный сервер |
| DPI_SERVER | Есть | Локальный ByeDPI SOCKS перед соединением с сервером |
| TOR | Есть | Локальный Tor SOCKS |
| TOR_SERVER | Есть | Соединение с сервером через Tor (`dialerProxy`) |
| SERVER_TOR | Нет | Исходящие соединения самого Tor должны идти через сервер |
| DPI_TOR | Нет | Нужен контролируемый upstream Tor через локальный DPI |
| DPI_TOR_SERVER | Нет | Нужен upstream Tor и дополнительный серверный outbound |
| DPI_SERVER_TOR | Нет | Нужен upstream Tor через сервер с DPI перед сервером |

`ChainProbeConfig` не добавляет freedom/direct fallback, блокирует UDP, слушает только
loopback, сохраняет серверный endpoint и credentials, отвергает вложенный существующий
proxy вместо его молчаливого затирания. Конфигурации нужны для **изолированных проб**,
не заменяют текущую конфигурацию VPN.

Перенаправить SOCKS-соединение к `127.0.0.1:9050` через удалённый сервер — НЕ способ
пропустить исходящий guard-трафик Tor через сервер. Такой ложной реализации здесь нет.
ByeDPI на телефоне не становится «последним хопом за удалённым Tor exit» перестановкой
тегов. Для изменения удалённого участка нужен компонент именно на этом участке.

## Реально выполнено

- **49 JVM-тестов, 0 failures/errors/skipped**: 36 policy/adapter-contract и 13 config.
- Kotlin 1.9.24, coroutines 1.8.1, JUnit 4.13.2; зависимости и SHA-256 закреплены в
  `tools/auto-chain-lab/dependencies.lock.json`.
- Реальный Xray 26.9.30, архив SHA-256:
  `f851110beaff16e78d643f0ccfd9524b4a44dfd59bae3e34bb52bba378f7690e`.
- Четыре положительных локальных TLS-пробы: SERVER, DPI_SERVER, TOR, TOR_SERVER.
  В каждой передано и сравнено **86 016 байт**; SHA-256 тела:
  `32bebe2817fec193b495a05392c64760b3d9ab28d07f3bc135d9ee606035b825`.
- Четыре отрицательных пробы: отключение обязательного SOCKS-хопа блокирует передачу,
  TLS origin не получает второй запрос. Обход обязательного хопа не обнаружен.
- Xray `run -test`, остановка дочернего Xray и listener threads — PASS.
- Python `py_compile`, Bash syntax и `git diff --check` — PASS.

**Tor и ByeDPI в этих пробах заменены строгими loopback SOCKS-фикстурами.** Реальны
Xray, TLS, проверка сертификата/тела и проксирование, но не Tor bootstrap, мосты,
ByeDPI packet desync, Telegram, YouTube или российский оператор. Фикстуры допускают
только два точных локальных назначения; публичные endpoints не проверяются. Тестовый
сертификат создаётся во временном каталоге и не добавляется в APK.

Повтор проверки:

```sh
JAVA_HOME=/path/to/jdk17 CHAIN_TEST_DEPS=/outside/repo/jvm-deps \
  bash tools/auto-chain-lab/run-jvm.sh
python3 tools/auto-chain-lab/smoke.py --xray /path/to/verified/xray \
  --configs /tmp/chain-probe-configs
```
