# Подбор цепочек Auto

База разработки: v1.2.54, `7d83d3e8b58a9673154c16c4a3fb9a2d200715dd`.
Нейромодель не выставляет PASS и не управляет допуском маршрута.

## Работа в приложении

После подключения Auto и завершения обычного ограниченного поиска серверов
`TunnelService` запускает отдельное фоновое сравнение цепочек. Текущее VPN-соединение
сохраняется во время измерений. Подбор не выполняется при ручном режиме, proxy-only,
явной маршрутизации сервисов, WARP-chain, игре, запрете фонового трафика или
защищаемой активной передаче. В настройках можно отключить сравнение и выбрать цель:
баланс, скорость загрузки или отклик.

Фактически реализованы схемы **от устройства к интернету**:

| Схема | Измерение и применение |
| --- | --- |
| Сервер | Выбранный сервер и его native-маска |
| DPI → сервер | Локальный DPI SOCKS, затем выбранный сервер |
| Tor | Готовый встроенный Tor SOCKS |
| Tor → сервер | Соединение с сервером через Tor (`dialerProxy`) |

Tor участвует только при включённом пользователем «Tor в Авто» и подтверждённой
готовности через аутентифицированный ControlPort. Холодный Tor не перезапускается
для каждого кандидата. Неизвестный или RU-выход Tor не допускается. UDP через Tor
не поддерживается. Проверка страны относится к проверенному потоку, а не гарантирует
неизменность всех будущих Tor circuits.

**Сервер → Tor, DPI → Tor и тройные схемы пока не реализованы и исключаются.**
Перенаправление `127.0.0.1:9050` через удалённый сервер не заменяет управление
upstream-соединениями Tor. Локальный ByeDPI не становится удалённым последним хопом
простым переставлением тегов.

## Проверки и ограничения

- Не более восьми уникальных кандидатов, без полного перебора каталога.
- Один монотонный бюджет сравнения 15 секунд, включая ожидание сериализации проб;
  до трёх секунд на кандидата. Подготовка уже работающих локальных адаптеров перед
  сравнением ограничена отдельно; это фоновая работа, не новый бюджет кнопки Auto.
- Измерения загрузки последовательны, чтобы не конкурировать друг с другом.
- Реальный runtime запускает отдельный Xray и проверяет HTTPS body transfer,
  Telegram MTProto и YouTube media. Ping/TCP-connect не являются доказательством.
- HTTPS использует существующее доказательство двух окон по 131072 байта; в образце
  сохраняются фактические байты и длительность, а не восстановленные из рейтинга.
- Telegram и YouTube PASS имеют приоритет над data-only UNKNOWN даже при меньшей
  скорости. Явный service FAIL исключает кандидата. Максимум один fallback при
  финализации, UNKNOWN не переименовывается в PASS.
- Лучший — только среди фактически измеренных вариантов; глобально самый быстрый
  сервер или доступность у конкретного оператора не обещаются.
- Переключение требует существенного выигрыша либо лучшего подтверждения сервисов;
  шум измерений и тот же chain ID не вызывают переподключение.
- Свежесть ограничена 60 секундами. Результат связан с точной конфигурацией, маской,
  DPI-стратегией, Tor-профилем, сетью и generation. Изменение сети, отмена, NEWNYM,
  устаревание или изменение настроек отбрасывает результат.
- Применяется именно измеренная цепочка, без случайной подмены маски. После применения
  выполняется проверка через действующий VPN. Неудача возвращает обычный Auto.
- Доказательство цепочки не записывается как доказательство отдельного сервера.
- Изолированные probe-конфиги не имеют direct fallback. В VPN сохраняются явные
  пользовательские direct-исключения и существующая LAN-политика.
- При отмене закрываются probe-соединения и Xray; ошибка cleanup запрещает следующую
  пробу. Coroutine timeout сам по себе не может прервать произвольный native-вызов;
  поздний запуск дополнительно проверяется и останавливается runtime-адаптером.

## Воспроизводимая локальная проверка

```sh
JAVA_HOME=/path/to/jdk17 CHAIN_TEST_DEPS=/outside/repo/jvm-deps \
  bash tools/auto-chain-lab/run-jvm.sh
# Полный Gradle JVM-набор дополнительно экспортирует LIVE_TOR_SERVER.json.
python3 tools/auto-chain-lab/smoke.py --xray /path/to/verified/xray \
  --configs /tmp/chain-probe-configs
```

Зависимости изолированных JVM-тестов закреплены в `dependencies.lock.json`.
Xray 26.9.30: SHA-256 архива
`f851110beaff16e78d643f0ccfd9524b4a44dfd59bae3e34bb52bba378f7690e`.
Рядом с бинарём нужны `geoip.dat` и `geosite.dat` из того же проверенного архива.

Локальный smoke проверяет пять конфигураций: SERVER, DPI_SERVER, TOR, TOR_SERVER и
LIVE_TOR_SERVER (конфиг действующего VPN-builder). Каждая передаёт и сравнивает
86016 байт TLS-тела, затем отключение обязательного хопа должно блокировать передачу.
Проверяются остановка Xray и отсутствие оставшихся fixture threads.

**Tor и DPI здесь заменены строгими loopback SOCKS-фикстурами.** Реальны Xray,
TLS, проверка сертификата и тела; это не проверка Tor bootstrap, мостов, packet desync,
Telegram, YouTube или оператора. Тестовый сертификат временный, в APK не добавляется.

## Android-регрессия и релиз

Debug-only драйвер использует production `AutoChainRunner`, реальные Xray/DPI и
аутентифицированный host fixture. Проверяет исключение мёртвого кандидата, измерение
DPI → сервер, применение через `connect(soft=true)` и передачу другого UID через VPN.
Никаких мокированных PASS. Release-вариант драйвера — no-op, вызов закрыт
`BuildConfig.DEBUG`. CI выполняет API 29/33 и существующую masks matrix без ослабления.

До фактического успешного завершения финальных gates публикация заблокирована
`tools/release-gates/readiness.json`. Физический телефон, мобильная сеть и реальные
Tor-мосты требуют отдельной проверки; fixture/emulator результаты её не заменяют.
