# Автоподбор 1.2.18 — скорость вместо первого ответа

- Первый ответ HTTPS больше не считается победителем по пропускной способности: короткая волна сравнивает два маршрута, затем при разрешении политики питания последовательно измеряет скачивание на двух подтверждённых кандидатах. Каждое измерение ограничено общим бюджетом 2500 мс; короткие неудачные измерения не становятся отрицательными примерами. При ограничении питания/игровом режиме используется доступный кэш/задержка, без тяжёлых замеров.
- Скорость имеет свою сеть, маску и дату измерения. HTTP 204 не продлевает свежесть скорости. Старые значения используются для выбора кандидатов на повторную проверку, но не выдаются за текущую скорость этой сети.
- В обычном Авто + leastPing активен один лучший проверенный маршрут, а не обязательные три медленных резерва. Остальные остаются в каталоге для восстановления. Явно выбранные другие балансировщики и ручной режим сохраняются. Избранное не добавляет медленную ноду обратно в основной автоматический маршрут.
- Каждое авто-подключение пересматривает выбор: прежний выбранный/запомненный сервер больше не закреплён навечно. Память сети и облако помогают при равной оценке, но не перекрывают более сильные измерения телефона.
- Скачивание весит заметно больше при ранжировании, неизвестная скорость не получает искусственно выгодные 300 мс. Облачная нагрузка/случайное распределение не переопределяют локально измеренный основной маршрут в Авто.
- Исправлены общий бюджет пробы (включает HTTPS и скачивание) и устаревший снимок состояния после фонового измерения. Отбор учитывает только действительно успешные результаты текущей волны, не старый works у неответившего кандидата.

Это оценка короткого скачивания, не обещание максимума на всех тысячах серверов или для каждого сервиса. Более быстрый cold-start требует компромисса с временем измерения; сравнивается ограниченный набор кандидатов. Сеть/нагрев/игровой режим могут отложить измерение. Телефонная нейросеть и правила приватности не изменены.
