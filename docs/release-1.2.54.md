# VLESS Card 1.2.54 — исправление подключения Tor

## Исправлено
- Устранена ошибка «ByeDPI не запущен» при выборе Tor на главном экране. Самостоятельному Tor больше не нужны процесс ByeDPI или выбранный VLESS-сервер.
- Сохранённый каталог VLESS не создаёт лишние серверные маршруты при самостоятельном Tor.
- Ошибка запуска Tor не переводит подключение в обычные Auto-повторы с масками или DPI-fallback. Прямой основной маршрут вместо Tor не включается.
- Сохранены пользовательские прямые исключения и настройка RU-direct/DNS. Обычные режимы ByeDPI, Hybrid и Servers по-прежнему требуют свои движки/серверы.

## Регрессии
Добавлены 10 JVM-тестов запуска Tor, включая настоящий путь выбора с главного экрана без фиктивного ByeDPI-порта. В E2E добавлена проверка настоящего Xray через закрытый локальный SOCKS-стенд без процесса ByeDPI. Это проверяет построение маршрута и передачу тестового тела, а не реальный Tor bootstrap.

## Границы выпуска
- Этот выпуск — только hotfix Tor. Незавершённая языковая модель и исследовательские эксперименты в APK не включены. Облачный каталог, ветка servers и release signing workflow не изменялись.
- Настройки мостов, интервал ротации и предпочтение быстрых измеренных выходов из 1.2.53 сохранены.
- Tor переносит TCP; произвольный UDP не поддерживается. NEWNYM не гарантирует новый IP строго по таймеру и не переносит уже открытые соединения.
- Реальные мосты, сети оператора, Telegram и воспроизведение YouTube на физическом телефоне в этой итерации не проверены. Эмулятор не доказывает их доступность.
- Общий зелёный gate masks matrix не означает успех каждой комбинации. В предварительном CI исправления было 610 успешных и 21 неуспешная ByeDPI-комбинация; существующий порог gate не изменялся. Точные причины этих отказов по публичным счётчикам не установлены.
