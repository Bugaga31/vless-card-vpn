# Подготовка 1.2.17 — адаптивный подбор и облачный control plane

- Подключение: два приоритетных HTTPS-маршрута с бюджетом 1200 мс; затем подтверждающая волна с обычным бюджетом 3500 мс. DNS/TCP-фильтр до 600 мс на кандидата, максимум 6 одновременно. TCP/204 не доказывают устойчивость большой передачи; короткий таймаут — не отрицательный пример для модели. Успех запускает соединение без ожидания остальных, следующие пары стартуют с задержкой 120 мс.
- Сетевые ключи: локально солёный хэш доступных SSID/шлюза/DNS, MCC/MNC для мобильной сети. Местоположение не запрашивается; при скрытом SSID сети с одинаковыми шлюзом/DNS могут совпасть — это ограничение честно сохранено. Старые семейства сетей используются как запасные подсказки.
- Реальные локальные наблюдения по сети+маске: EMA успеха, задержки, джиттер, затухание доверия, мягкие штрафы 2/15/120 минут. Результаты облака не увеличивают локальные счётчики. Независимая PhoneLearning не превращена в VPN-модель.
- Каскад поиска масок: сначала простой путь/уже доказанные маски, затем фрагментация, DPI, UDP/WARP. Каждый этап запускает только нужные ему движки. Для эскалации выбирается небольшой разнообразный набор узлов.
- Фоновый резерв: два подозрительных окна Tx/Rx по 5 секунд, дополнительная HTTP-проверка, затем поиск подтверждённой запасной ноды. Только в авто-режиме и при разрешении power policy. VPN/TUN сохраняется при soft-переключении, но сохранность всех существующих TCP-сессий не гарантируется.
- Публичный `cloud-manifest.json`: gold/silver и quarantine. Gold требует фактически наблюдавшегося суточного окна и условий по REALITY/Vision/задержке, неизвестный суточный аптайм — null. Карантинные ссылки не распространяются в манифесте; пользовательские/выбранные серверы не удаляются из-за зарубежного измерения. Реальная проверка Xray остаётся обязательной на телефоне.
- Безопасные облачные рецепты: существующие IDs масок/DPI плюс ограниченные структурированные параметры фрагментации. Нет удалённого кода, произвольных argv, отключения TLS или подмены SNI REALITY. `config/cloud-recipes.json` обновляется независимо от APK; пресеты не объявляются проверенными на МТС/Билайн и других операторах без измерений.
- Чтение облака: DoH, зеркало CDN, системный DNS, уже доступный VPN/ByeDPI/WARP-прокси, временный локальный ByeDPI при разрешении политики питания. Никаких новых WARP-аккаунтов ради чтения облака. Приватные CloudSync-бэкапы и их токены никогда не отправляются на публичные зеркала. Кэш не задерживает кнопку подключения.
- Скоринг: облачный prior + реальные сетевые наблюдения; один UCB-слот для фоновой проверки новых кандидатов, без неподтверждённого переключения; локальное доверие растёт постепенно и затухает со временем. Внешние operator tags доступны только из реальных агрегатов. Новая отправка отчётов с телефонов не включена: нужен согласованный защищённый intake, лимиты и отзывные учётные данные, без общего ключа в APK.
- CI: кэш нативных библиотек с fingerprint исходников/скриптов/NDK/ABI и проверкой SHA-256 + ELF архитектуры каждого бинарника. При повреждении — пересборка. Secrets/Keystore не кэшируются. E2E использует явные headless-флаги; нативные ABI/KVM и подготовка разрешений сохраняются.
- Тесты сгруппированы по темам, старые IDs сохранены в именах и `docs/test-map.md`. Старые заметки перенесены в `docs/archive/releases/` без удаления текста; выпуск умеет искать заметки в архиве и добавляет generated commit notes.

## Проверки и незавершённые внешние зависимости
Локальные JVM/Python тесты и CI фиксируются по результатам, не заранее. Реальные телефоны/провайдеры и заявленные 0,5–3 секунды/85% успехов пока не измерены. Телеметрия остаётся отключённой; endpoint/authentication/consent flow требуют отдельных входных данных. Эта заметка не означает опубликованный APK.

## Дополнение: питание и диагностика телефона
- Единый событийный наблюдатель SCREEN_OFF/ON, батареи, экономии и ThermalStatus (Android 10+). При moderate thermal и lowMemory TCP/HTTPS-параллелизм ограничен двумя, облачные фоновые обновления отложены; размер пробного конфига также ограничен. Уже выполняющаяся волна завершается безопасно, действующий VPN не отключается.
- Таймеры домашнего экрана, настроек и диагностики работают только в RESUMED. Бесконечная анимация кнопки больше не создаётся в простое или при ограничении нагрузки. Скорость рассчитывается по фактическому времени между выборками. Уведомление и резервный scout ждут события включения экрана вместо постоянного опроса; watchdog во сне значительно реже просыпается, экран разблокировки и смена сети остаются событиями восстановления.
- Совместимый виртуальный MTU: Wi-Fi 1400, мобильная сеть 1360, WARP 1280 с учётом доступного меньшего link MTU; jumbo 8500 больше не включается. Это не измерение физического path MTU и не гарантия скорости.
- Игровая сессия: явно включаемая, до 60 минут, только в текущем процессе. Откладывает облачное обслуживание, резервный scout и DeviceCoachJob. Новые авто-выборы учитывают HTTPS EMA/jitter и надёжность, без выдуманных потерь UDP и без разрыва текущего туннеля. Не повышает системные приоритеты, не управляет частотами и другими приложениями.
- Экран телефона: реальный статус battery exemption и кнопка системного запроса только по нажатию; Private DNS берётся из LinkProperties основной сети (Android 9+). Активный DNS не объявляется неисправным без диагностики; никаких автоматических изменений DNS.
- Сетевой fingerprint берётся с доступной основной сети, а не виртуального gateway VPN. Правила per-app исключений сохранены: только пользовательские настройки, игровой режим не исключает приложения сам.
- Sniffing routeOnly остаётся: http/tls, QUIC только если он разрешён настройкой, чтобы не сломать маршрутизацию. При создании конфигурации в ограниченном режиме Xray/hev используют error logging; работающий туннель ради смены логов не перезапускается.
- Исправлена упаковка JNI: два native-cache.json внутри корней библиотек конфликтовали в mergeDebugJniLibFolders. Манифесты вынесены в отдельные боковые файлы, старые удаляются при проверке; добавлена регрессия.
- Не урезаны автоматически geosite/geoip и правила маршрутизации: это могло бы изменить безопасность и охват исключений. Нехватка памяти уменьшает необязательную нагрузку, не превращает программу в RAM-cleaner. Экономия 40%, ускорение игр вдвое и охлаждение процессора не заявляются без измерений.
