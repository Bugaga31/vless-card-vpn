# 1.2.21 — Новая подписка и сохранение быстрого маршрута

- Добавлена запрошенная подписка Diman331: в каталог приложения, источники по умолчанию и облачный сборщик. На существующих установках добавляется один раз; последующее удаление пользователем сохраняется. Если автообновление включено, новая подписка загружается отдельно при запуске, не дожидаясь 12-часового обновления остальных источников и не задерживая рабочий VPN.
- Исправлена потеря результата автоподбора: Авто запускает именно измеренную маску для текущей сети, а не случайную из исторических `goodMasks`. Ручная ротация сохранена. Экстренный безопасный повтор без маски по-прежнему возможен.
- Авто больше не заменяет настроенный `leastPing` на `leastLoad` при запуске туннеля. Обычное Авто использует один основной маршрут с наибольшей подтверждённой скоростью скачивания; явно выбранные другие балансировщики сохраняются. Игровой режим сохраняет приоритет задержки.
- Низкая задержка сама по себе не завершает поиск. Если лучший измеренный маршрут медленнее мягкого ориентира 5 Мбит/с либо его скорость не подтверждена свежим замером, разрешена одна дополнительная волна до четырёх разных серверов. Проверка доступности идёт параллельно, измерения скорости — последовательно. Даже один известный рабочий сервер больше не блокирует сравнение с новыми кандидатами.
- Для медленного победителя или конфигурации с дроблением/тяжёлыми слоями Авто пробует до двух совместимых лёгких вариантов маскировки: исходные параметры ссылки и/или браузерный профиль с мягким дроблением TLS. Новая маска применяется только после успешного HTTPS-запроса и полного контрольного скачивания с большей измеренной скоростью. Неудачный короткий тест не удаляет рабочий вариант и не создаёт ложный штраф.
- Смена маски и привязка измерения к сети сохраняются вместе. При повторной предварительной проверке учитывается не только ID сервера, но и маска: улучшение на том же сервере тоже требует применения новой конфигурации ядром. Проверки после смены Wi-Fi/мобильной сети не применяются; отмена пользователем и ограничения нагрева, энергосбережения и игрового режима соблюдаются.
- Дополнительный скоростной поиск имеет общий целевой бюджет 14 секунд после начальной проверки доступности, включая сравнение финалистов, резервную волну и подбор маски. Это не обещание времени всего подключения: системный запуск ядра, DNS, обновление подписок и экстренное восстановление могут занять больше. Нет сканирования всего каталога или бесконечного перебора масок перед каждым стартом.
- Облачные замеры пропускной способности теперь выполняются по одному, а не 12 конкурирующими скачиваниями. За запуск проверяется до 24 конфигураций: половина мест отведена лидерам, оставшиеся — давно не измеренным и новым маршрутам, с разнообразием хостов. Неудачное скачивание снимает старый положительный рейтинг, а не оставляет его через EMA.
- `speed.json` содержит время каждого изолированного замера. Телефон не использует старые параллельные, недатированные, будущие или старше часа облачные скорости. Манифест не выдаёт старую скорость за свежую и ранжирует измеренную пропускную способность перед общим смешанным рейтингом. Это подсказка к очереди проверки, не подтверждение доступности у пользователя.
- Загрузка манифеста и рейтинга скорости запускается независимо: задержка одного не задерживает другое. После сбоя манифест можно повторно запросить через минуту, а не ждать десять минут.
- Добавлены регрессионные проверки новой подписки, миграции, её удаления, масок, сохранения сетевых измерений и извлечения HTTPS/Gist-источников облаком. Импорт модуля облачного каталога больше не запускает сетевой сканер.

Скорость до контрольного узла не гарантирует максимальную скорость YouTube, Gemini или каждого сайта. Облачная проверка из GitHub не доказывает доступность у оператора пользователя. Проверки на реальном телефоне и измерения в сети пользователя в этом выпуске не заявляются. Сторонняя публичная подписка и её серверы не принадлежат разработчику приложения; их доступность и доверенность не гарантируются.
