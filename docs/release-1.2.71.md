# VLESS Card 1.2.71 · Experimental — адаптивная очередь Auto

## Что изменено
- **Приоритет начала подключения.** Одна общая очередь ProbeArbiter для обычных, цепочных и скоростных тестов. Фоновые real-пробы разбиты на пачки до 6 вариантов (меньше при ограничениях телефона). Между пачками ядро освобождается; ожидающая foreground-волна получает приоритет перед новой фоновой. Уже идущая проба не прерывается, фиксированное время подключения не обещается. Отмена ожидания снимает запрос приоритета; временные ядра закрываются перед освобождением permit.
- **Скоростные пробы тоже уступают очередь.** Вместо одной блокировки на серию из нескольких серверов — отдельный permit и временное ядро на каждый вариант. Измерения остаются последовательными, не делят канал одновременно.
- **Адаптивный порядок кандидатов.** Beta(2,2)-сглаживание локальных успехов, 30-минутный half-life, свежий EWMA, ограниченный вклад измеренной скорости и штраф latency + 2×jitter. Облачный prior — только малый hint. Это эвристика приоритета проб, не калиброванная вероятность, не нейросеть и не разрешение переключить живой маршрут. Игровой порядок задержки сохранён.
- **Исправлена очередь отложенных маршрутов.** Облако и полный каталог не возвращают cooling-кандидата в первую волну, если есть готовые альтернативы. Если отложены все, разрешён только один пробный кандидат этой волны. Когда есть маршруты без свежего сервисного отказа, известный отказ не внедряется обратно облачной подсказкой.
- **Разнесение повторных попыток.** Существующие soft cooldown HTTPS и Telegram дополнены детерминированным jitter 0–20% по сети/серверу/маске. Это небольшое разнесение внутри устройства, не гарантия глобального распределения нагрузки всех телефонов. Успешная проба снимает соответствующий cooldown; отмена или неизвестный результат не становятся отказом.
- **Бюджет необязательных резервов.** Token bucket в памяти: до двух стартовых волн, затем одна пополняемая волна в минуту на физическую сеть, до восьми записей сетей. Это лимит числа волн, НЕ лимит байт. Действующие ограничения нагрузки/трафика/звонков и пауза ускорения учитываются. Ручное подключение и аварийное восстановление этим bucket не ограничены.
- **Telegram для резервов.** Фоновый запасной Auto-маршрут теперь явно требует Telegram MTProto, а не только HTTPS.
- **Наблюдаемость.** Паспорт показывает тип текущей проверки, число ожидающих foreground-запросов и последнее ожидание permit. Это не сетевой ping. Ручной JSON-отчёт содержит только фиксированные coarse поля, без адресов, ключей, имён сетей и автоматической отправки.

## Что НЕ заявляется
Нет доказательства ускорения на конкретном телефоне, улучшения у всех операторов, невидимости DPI, лидерства или монополии. Не менялись SNI, TLS-верификация, ключи, правила прямого обхода и требования живой проверки маршрута. Сервисные пробы через SOCKS не доказывают полный путь app→TUN, авторизацию Telegram, все DC, media или звонки. Историческая память и облачные рейтинги не заменяют текущую проверку.

## Проверки
В репозиторий добавлены шесть синтетических регрессионных сценариев для очереди, ограниченности рейтинга и token bucket. **Они не запускались.** По прежнему запросу владельца unit-тесты, lint, эмулятор, физический телефон и визуальная проверка UI пропущены. Для публикации выполнены только компиляция, постоянная Beta-подпись и проверка целостности/пакета APK. Это Experimental; стабильный канал и старые релизы не заменяются.
