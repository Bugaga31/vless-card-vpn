# Единое облако независимо от версии APK

## Что уже общее

В локально доступных тегах v1.2.0–v1.2.50 обнаружен один облачный workflow:
`.github/workflows/cloud-servers.yml`. Его исторические версии — не независимые
облака: запускать все старые workflow параллельно нельзя. Это создаст дубли,
конкурирующую публикацию и возврат устаревших правил.

| Компонент | Общий источник / состояние | Роль |
| --- | --- | --- |
| Сборщик публичных конфигураций | `scripts/cloud_servers.py`, `source-map.json` | Каталог и происхождение |
| Проверки Xray и скорости | `cloud_real.py`, `history.json`, `speed.json` | Фактическая передача и ограниченная история |
| Существующие агрегаты отчётов | `cloud_reports.py`, `cloud_state.json`, `cloud.json` | Сохранение допустимого прежнего состояния; не включение новой телеметрии |
| Статистика масок | `cloud_masks.py`, `mask-stats.json` | Существующие измеренные подсказки |
| Единый манифест | `cloud_manifest.py`, `cloud-manifest.json` | Объединённые данные для телефона |
| Частная резервная копия | Android `CloudSync` | Отдельная пользовательская копия; НЕ смешивается с публичным каталогом |

Все публичные данные читаются приложением из постоянной ветки `servers`.
Обновление версии APK не создаёт новую ветку состояния и не сбрасывает её.
Tor TOP100 — отдельный необязательный источник мостов, не новое облако и не
доказательство доступности мостов. Пользовательские ключи, частные конфигурации,
резервные копии и содержимое трафика не объединяются и не переносятся.

## Изменения непрерывности

1. До сбора checkout читает ровно одну ревизию `servers`.
2. `cloud_state.py freeze` проверяет наличие и JSON-объект всех трёх файлов памяти,
   ограничивает размер каждого 128 MiB, запрещает symlink, сохраняет SHA-256 и SHA
   ревизии. Лимит учитывает существующий `history.json` размером около 39 MB.
3. Все shards и этапы используют этот один снимок. Ошибка чтения/JSON/hash —
   остановка; больше нет сетевого `except: return {}` с последующей перезаписью.
4. Ошибка объединения отчётов блокирует публикацию, а не замалчивается.
5. После проверок создаётся обычный commit поверх исходной ревизии `servers`.
   История Git сохраняется. Никаких `git init`/force push.
6. Если ветка успела измениться, публикация отклоняется. Обновление удалённой ветки
   между проверкой и push также отклонит обычный fast-forward push.
7. Копируется только заданный набор результатов. Внутренние очереди, снимок и
   очередь подтверждений отчётов не публикуются. Неизвестные прежние файлы ветки
   сохраняются, а не стираются.
8. Отчёты закрываются только после успешной постоянной публикации. Это не
   транзакция между Git и Issues: при ошибке закрытия отчёт остаётся открытым;
   строгая exactly-once обработка между этими сервисами не заявляется.
9. `continuity.json` содержит предыдущий SHA и хэши результатов, без содержимого
   отчётов и идентификаторов устройств. Actions закреплены полными SHA;
   права записи выдаются только публикации и существующему планировщику.

## Неизменяемые ограничения

- Свежесть и TTL остаются прежними: накопление не превращает старые PASS и скорости
  в текущие доказательства работоспособности.
- Результат GitHub runner не доказывает доступность у оператора пользователя.
- Авто на телефоне обязано проверять маршрут; облако даёт подсказки, не PASS.
- Существующая отправка отчётов из APK не включается, новых secrets нет.
- Старые архивы не сливаются слепо: дубликаты наблюдений испортят статистику.
- Частные backup credentials, формат локального обучения и APK не изменяются.
- Workflow тестовой ветки выполняет только локальные регрессии. Сбор, сетевые
  проверки, публикация `servers` и следующий запуск разрешены только на `main`.
- Эта отдельная ветка сама по себе не меняет действующее облако до интеграции.

## Проверки

`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s scripts -p 'test_cloud_*.py'`

Регрессии проверяют единый снимок, сохранение между поколениями, отсутствие
сетевого fallback, пропажу/порчу/подмену/превышение размера, старые FAIL,
сохранение посторонних файлов, запрет частичной публикации и порядок подтверждения
отчётов. Публичные VPN endpoints при этих тестах не используются.
