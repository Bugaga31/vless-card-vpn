## Принятые решения владельца

- Общий целевой бюджет пользовательской попытки 15 секунд, не гарантия подключения.
- UNKNOWN не PASS и не FAIL; допускается один честно обозначенный базовый fallback.
- Полный каталог отдельно, не на пути кнопки подключения.
- Дизайн и конкуренты — другая задача.

## Карта пути

Кнопка → создание монотонного deadline → ожидание Store/ядра → до 8 приоритетных кандидатов → ограниченные независимые TLS/данные → сервисные финалисты и изолированная скорость в оставшемся поисковом бюджете → A-пул либо один B-маршрут → запуск фактической цепочки и обязательный контроль данных → подключение → ограниченная фоновая сервисная проверка и резервы.

- Поисковая фаза использует только остаток до резерва 5 секунд; смена этапа время не обнуляет.
- Обновление подписок не входит в кнопку подключения: пустой каталог объясняется отдельно, без скрытого ожидания сетевых повторов.
- Native/JNI не имеют гарантированного принудительного прерывания. Поздний результат не допускается; завершение очистки может выйти за deadline.
- Облачный refresh асинхронен; stale/cloud data не создаёт локальный PASS.
- Форматы пользовательских данных/обучения не меняются, миграция не нужна.

## Проверки

Результаты нового кандидата будут внесены после фактического выполнения. Предыдущие 504 JVM-теста относятся к отменённому кандидату, не к этому исправлению.

## Не проверено

Публичное YouTube-видео, реальные Telegram-сценарии, физический телефон, сеть оператора, до/после по времени/скорости/трафику. Проценты улучшения не заявляются.
