# 1.2.80 Experimental — запуск WARP и строгие проверки маскировок

## WARP
- Исправлена передача подтверждённой точки WARP в запуск VPN: явная настройка выбирает один основной маршрут в режиме «Серверы», отключая непроверенную цепочку WARP. Режим «Авто» не подменяется скрытым прямым обходом.
- Выбор возможен только после свежих HTTPS и MTProto-проверок для той же сети и маски, с временем ответа каждой 1–500 мс. При смене сети, неуспехе или отмене прежний выбор не заменяется. Более быстрые ответы, чем 50 мс, разрешены.
- Новая попытка добавляет точки, не удаляя прежние аккаунты/серверы и результаты при неудаче.
- По умолчанию регистрируется один аккаунт вместо трёх. Явный параметр ограничен 1–3 аккаунтами. На один аккаунт одновременно проверяется только один WireGuard-туннель.
- API-запросы отменяемые: отмена действия отменяет принадлежащий ему HTTP-вызов. Общие запросы VPN не отменяются. HTTP-вызов ограничен 6 секундами; этап регистрации и WARP+ — по 12 секунд на аккаунт. Для WARP+ не более двух различных ключей, общий поиск точек до 90 секунд, всё действие до 120 секунд. Это верхние бюджеты, а не обещание мгновенного соединения.
- Ответ API ограничен 64 КиБ, переадресации выключены, SOCKS-порты проверяются и дедуплицируются. Ошибки/неполный ответ не означают успешную активацию WARP+.
- IPv4-параметр с /32 больше не получает второй /32; повреждённые адреса, другой префикс и reserved/client_id не принимаются.
- По одному неудачному поиску приложение больше не объявляет UDP заблокированным. Финальный статус WARP проверяется после запуска, а не обещается заранее.

## Алгоритмы масок
- В строгом режиме повторная проверка обязательна даже для одной найденной точки. При пропущенной/неуспешной проверке или исчерпанном бюджете маска не применяется. Повторная проба действительно запускает Telegram и требует его результата. Успех HTTPS не выдаётся за работоспособность Telegram.
- Политика подтверждения двух замеров самостоятельно отклоняет неизвестную/медленную задержку более 500 мс; сохраняется меньшая из двух измеренных скоростей.
- Последняя отменённая/неопределённая проба не позволяет алгоритму экспериментов использовать предыдущий успех как актуальную оценку. Неопределённость не превращается в отрицательный результат сервера; слот исследования сохраняется.
- Это исправления запуска и достоверности измерений. Новых фиктивных «невидимых протоколов» нет; UDP noise не объявляется настоящим QUIC или гарантированным обходом любого DPI.

## Очистка
Автоматическое удаление не добавлено. По-прежнему только собственный временный кэш старше суток, ручной анализ и отдельное подтверждение; не RAM, не чужие приложения и не файлы телефона. Если удаление действительно происходит само, нужны отдельные воспроизводимые шаги: такой сценарий не считается нормой.

## Проверки
30 новых fixture-сценариев проверяют выбор WARP, сохранение текущего маршрута, сеть/маску/свежесть/Telegram/задержки, /32, отмену принадлежащего HTTP-вызова, предельный размер ответа, строгую повторную проверку и неизвестный результат эксперимента. Они запускаются на JVM debug/release и Android. API-тесты используют только перехватчики с фиктивным доменом: настоящие Cloudflare-аккаунты не регистрируются, публичные ключи в тестах не активируются.

Повторяются предыдущие native TLS/Hello/DC/очередь/кэш/согласие/UI регрессии: 86 Android-тестов и 12 фактических снимков синтетических состояний. Перед выпуском проверяются JVM debug/release, lint, host-регрессии, совпадение production-исходников и визуальная проверка снимков.

Физический телефон, реальный WARP-сервер, полный TUN, Telegram-аккаунт и DPI оператора не проверялись. Выпуск не гарантирует доступность публичных точек WARP и не доказывает превосходство над всеми VPN.
