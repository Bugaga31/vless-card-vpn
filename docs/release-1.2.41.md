# 1.2.41 — Tor в авто-режиме + устойчивость каталога

Продолжение поглощения tor-rotator-vless (см. [1.2.40](release-1.2.40.md)) и
разбор «конкурентов» — комьюнити-списков конфигов (harvester-подобные сборщики,
vpn-configs-for-russia, AetrisVPN и др.).

## Tor-over-VLESS для сервисов (`torRouting`)

Новая настройка: выбранные сервисы (Discord, Claude, Gemini, ChatGPT…)
маршрутизируются в Xray на локальный Tor SOCKS (127.0.0.1:9050, порт Tor Card).

Цепочка получается бесплатно: пакеты самого Tor не исключаются из TUN
(excludedApplications содержит только uid приложения), поэтому Tor-трафик
едет через туннель → Tor оказывается завёрнут в VLESS без dialerProxy и
без второго приложения. Ротация выхода (`torRotation`) продолжает работать
в фоне — в авто-режиме цикл запускается на каждом успешном коннекте.

- outbound `tor` (socks) добавляется только при включённом `torRouting` и
  непустом списке сервисов;
- для сервисов из списка правило пинается на `tor` вместо основного
  балансира, остальные сервисы и весь остальной трафик — как раньше;
- Discord добавлен в `ServiceRoutes.targets` — теперь он участвует в
  замерах и в сервисных балансирах наравне с Telegram/YouTube.

Если Tor не запущен (Tor Card не поднимал Termux), сервисы из списка
не откроются — флаг стоит включать вместе с Tor Card.

## Устойчивость Auto-пула: одна подсеть/один SNI = один слот

`AutoEligibility.independent` раньше дедуплицировал только WireGuard-аккаунты.
Теперь каталог делится по « blast radius»:

- не более одного сервера на /24-подсеть (IP-хосты) или на домен второго
  уровня (hostname-хосты);
- не более одного сервера на SNI (Reality/по маске) — один блок сертификата
  или блок подсети хостера больше не съедает восемь слотов пула.

Идея взята у комьюнити-сборщиков (ASN-фильтрация в harvester-подобных
инструментах, дедуп в kort0881/stats-подходе) — здесь она встроена в
выбор Auto, а не в ручную выжимку списков.
