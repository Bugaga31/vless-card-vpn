# VLESS Card 1.2.15 — сначала интернет, подробные проверки потом

## Однокнопочный сценарий
- Сохранённые результаты этой сети, локальное обучение и облачный кэш используются до массовых проверок. Свежий HTTP-запрос к облаку выполняется отдельно и не задерживает кнопку подключения.
- На холодном старте первая волна — максимум 8 разных кандидатов. После первого успешного HTTPS-ответа выбранный маршрут сразу передаётся туннелю; не нужно ждать остальные ответы, YouTube, Telegram или загрузку 256 КБ. Следующая волна максимум 16 кандидатов — только когда первая не нашла рабочий путь.
- Короткая HTTPS-попытка ограничена 3.5 секундами. Это не обещание подключения всего телефона за 3.5 секунды: DNS, получение подписки, TLS pinning, запуск Xray/TUN, число волн и поведение сети занимают дополнительное время. На полностью блокированной сети остаются поиск масок и обход DPI.
- При пустом списке первый успешно загруженный источник подписки уже проверяется — другие источники дозагружаются без ожидания перед первым найденным туннелем. Отмена подключения запрещает поздним callback запускать VPN снова.
- Подготовка при открытии приложения больше не проводит полную Xray-проверку 120 серверов. Старая подписка не заставляет откладывать имеющийся рабочий каталог до её обновления.
- Первая проверка уже запущенного VPN тоже короткая. Надпись «HTTPS работает» не выдаётся за проверку скорости, YouTube, Telegram или аккаунта Gemini.

## Накопленные данные и облако
- Кэш общего облака применяется сразу перед Auto: сетевые профили/маски, модель и опубликованные рабочие серверы. Рейтинг скоростей/оператора загружается из сохранённых данных без ожидания HTTP, приоритет первых кандидатов учитывает сетевую память, облачный рейтинг и локальную модель.
- На главном экране виден статус рейтинга: сохранённый, свежий, пустой или недоступный. При ошибке остаётся локальная память; ответа облака нет — успех не выдумывается.
- Небольшие периодические чтения облака доступны на мобильной сети отдельно от тяжёлых загрузок, при сохранении ограничений температуры, низкого заряда, Data Saver, паузы и сна.
- Облачный рейтинг из датацентра — подсказка, не гарантия работы на операторе. Перед первым холодным подключением требуется локальный HTTPS-успех. Новая версия не возвращает общий секрет в APK: автоматическая отправка телефонных отчётов остаётся отключённой. Облако резервных копий не является измерителем скорости серверов.

## Фон и зарубежные сервисы
- Каталог просматривается небольшими волнами (24 TCP/DNS кандидата, до 6 подробных Xray-проверок), порядок продвигается по давно не проверенным серверам. Первое подробное дополнение — до 12 кандидатов вместо 60. Нет обещания бесконечного сканирования без расходов батареи/трафика.
- Поиск не мешает активному потоку и останавливает новые необязательные фазы при тепловых/энергетических ограничениях. Запросы тестов можно прервать при отмене; тестовое ядро закрывается через finally.
- Gemini, ChatGPT, Claude, Spotify имеют отдельные короткие HTTPS-проверки по выбранным серверам, без разрешения Usage Access. Начальный круг проверяется по очереди, последующие проверки реже. Пробы и туннель не используют один общий тестовый Xray mutex для жизненного цикла VPN.
- Успешные HTTPS-маршруты сервиса закрепляются в доменных правилах Xray, с небольшим гистерезисом выбора. Только выбранные серверы текущей сети, максимум два пути, fallback для сервисного балансировщика. Неизвестные/просроченные ссылки не создают несуществующие outbound-теги; WARP-chain не переопределяется сервисными правилами. Пользовательские правила «всегда напрямую» сохраняют приоритет.
- Сервисный монитор независим от длинного цикла полного поиска и не требует открытия соответствующего приложения. Доступность публичной страницы не гарантирует доступ к аккаунту, региональным функциям, оплате или стабильную высокую скорость всех зарубежных сервисов.

## Проверки
JVM-регрессии: ограничение первого каталога, память сети/облачный приоритет, разнообразие адресов, недопущение чужих кандидатов, сетевой TTL сервисных результатов, гистерезис/отказ, корректность Xray domain/balancer/fallback, отделение мобильных облачных чтений от тяжёлого обслуживания. Полный native build, подпись и Android 11/14 install+Keystore проверки выполняются release CI. Задержка/скорость на физическом телефоне и сетях РФ пока не измерены; тестовый успех не заменяет эти замеры.
